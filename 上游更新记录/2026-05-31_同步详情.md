## 关键技术点：为什么用 squash 而非 merge

- 最初用 `git merge --no-ff` 把上游并进来，但上游 commit `41f2fb1` 自身的树里含 94MB 实拍图。只要它成为 main 的祖先，blob 就**可达**，`git push` 会连 94MB 一起上传，排除等于白做。
- 实证：merge 后 `git rev-list --objects main | grep -c powerstep_images` = **24**。
- 修正：`git reset --soft 111fd9b` 回退、保留已暂存的目标内容，重新做**单亲 squash 提交**（不含上游父节点）。
- 修正后实证：`git rev-list --objects main | grep -c powerstep_images` = **0**，push 体积 ≈ 7.78MB。

### 副作用与提醒

因为是 squash 而非 merge，上游 `af0bb58..6f7b33f` 不是 main 的祖先，未来 `git log HEAD..upstream/main` 会**重新列出**这 5 个 commit。它们已在本次同步（仅排除大图），**不要误判为未同步**。后续若只是想确认「是否有更早于 6f7b33f 的新上游提交」，以本记录为准。
