## 🔍 主要变化

### MotorBridge v0.4.6 → v0.4.7（3 commit，⭐ 对症遥操作超时）
- `bbcca2d fix(damiao)`: 模式切换加固 + 参数持久化。写寄存器改为等 `0x55` write-ack，3 次重试（`WRITE_REGISTER_ACK_ATTEMPTS=3` / `ACK_TIMEOUT_MS=50` / `RETRY_GAP_MS=20`）；`ensure_control_mode` 改单一共享超时预算（旧版每步各复用完整 timeout，最坏 N×timeout）+ 模式切换前后持位（`prepare_for_mode_switch`/`finish_mode_switch`）；`store_parameters` 先 disable 再存参且不自动 re-enable。
- `dadfe8d fix(dm-serial)`: 串口 I/O 超时预算 **1ms → 10ms**（`DmSerialBus::open()`）。1ms 在 USB-CAN/USB-串口适配器上过紧，写易触发 `Operation timed out`。
- `2b7b350 release: prepare v0.4.7`。
- 达妙路径 +约 600 行新单测；Python API 100% 兼容（`api_surface.json` 仅版本号字段变化）。
- **判断**：直接对症我们 06-13 遥操作时的 `dm-serial write failed: Operation timed out` 和 `clear_error failed ... timed out`。dm-serial 放宽是"对症"修复而非偶然相关。
- ⚠️ **唯一需现场验证点**：写寄存器现等 write-ack——若 DM4340P/DM4310 固件不回 `0x55` 写回执，原本静默成功的写会变成超时报错（影响 `ensure_control_mode` 内部 `write_register_u32(10, mode)`）。无法纯离线确认，**待下次上电冒烟测**。若出现 `register N write ack not received within 50ms` 即固件不发回执，需回退 0.4.5 并向上游反馈。
